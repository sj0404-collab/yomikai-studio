# Эмулятор под тесты читалки (копия APKForge Studio)

Это **клон** APKForge Studio (`sj0404-collab/apkforge-studio`), доработанный под
нашу читалку. 29.10 копия восстановлена заново с GitHub: в прежней `forge-koma`
пропали `src/components` (остались только мосты), и стенд не запускался.
Добавлен один файл с мостами (`src/lib/komaShim.ts`), KOMA-режим в эмуляторе и
чтение плагина из `koma/plugins/`.

Зачем копия, а не «как есть»: обычный эмулятор студии показывает страницу из
`assets/webapp/index.html` побайтово (это уже давало честный прогон), но **не
трогает тот код, который работает только в АПК** — системный голос, нативную
панель чтения, оболочку. Именно там и живут жалобы «голос не тот» и «панель
поехала». Здесь этот код подменяется мостами с теми же именами и методами.

## Что добавлено

| файл | что делает |
|---|---|
| `src/lib/komaShim.ts` | мосты `KomaSpeech`, `KomaUi`, `KomaApp`, `KomaPlugins` для страницы: мок системного TTS с очередью и событиями `start/end/error`, нативная панель (состояние + команды), версия оболочки и «обновление» |
| `src/components/Emulator.tsx` | режим `?koma=1`: вставка мостов в страницу, панель чтения **под «экраном»** (как нативная полоса под WebView), кнопки ▶/⏸/⏭/⟲/⏹, счётчик фраз, опрос состояния мостов |
| `koma/live.py` | **живой прогон на настоящей странице**: поставить АПК → манга и модели → распознать → прочитать → напечатать, что и в каком порядке ушло в голос, сверить с эталоном, снять скриншоты |
| `koma/run.py` | синтетический прогон (быстрая проверка мостов и кнопок) |
| `koma/setup.sh` | вернуть стенд после сброса песочницы: библиотеки браузера, npm, playwright, подкачка, запуск студии |

## Запуск

```bash
bash koma/setup.sh --run        # поставить всё и сразу прогнать
# или по шагам:
npx vite --host 0.0.0.0 --port 5174        # студия
python3 koma/run.py                        # прогон (сам скачает АПК, страницу, модели)
```

В браузере: **http://localhost:5174/?koma=1** — та же студия, но с мостами и
панелью чтения. Без `?koma=1` — обычный эмулятор.

Скриншоты прогона: `/home/user/koma-lab/shots/`.

## Что теперь проверяется (и раньше было нельзя)

- нативная панель показывает **именно ту реплику**, что звучит, и её место в
  очереди («реплика 2 из 3 · полоса 1 из 3 · Android TTS»);
- ▶ читает с начала полосы, ⏸ ставит паузу, ⏭ уводит на следующую, ⟲ повторяет
  текущую, ⏹ останавливает и убирает панель;
- голос получает **все** реплики по порядку, без дублей и без потерь;
- лента не дёргается (считаем смены направления по кадрам прокрутки).

## Чего этот стенд не делает — и не притворяется

- **Звука нет**: голос — мок с очередью `QUEUE_FLUSH` и событиями Android TTS.
  Голос и движок (Tera TTS) проверяются только на телефоне.
- **Kotlin-движок чтения** (ReadEngine) и нативный **Lens** в браузере не
  работают: страница в эмуляторе считает реплики своим движком. Контракт моста
  `KomaRead` закреплён юнит-тестами (`test-read-native.cjs`,
  `apk/tools/readtest`), а не этим прогоном.
- ONNX-распознавание, словарь, склейка реплик, прокрутка, интерфейс — настоящие.

## Обновиться из upstream

```bash
git -C /tmp clone --depth 1 https://github.com/sj0404-collab/apkforge-studio.git forge-src
cp -a /tmp/forge-src/src/components src/ && cp -a /tmp/forge-src/src/lib/*.ts src/lib/
# затем вернуть правки: src/lib/komaShim.ts и блоки `koma` в Emulator.tsx
```

## Живой прогон на настоящей странице (29.10)

```
python3 koma/live.py            # страница /home/user/koma-lab/dense-a.jpg, эталон dense-expected.json
```

Что проверяется и что печатается на экран:

* какие реплики распознались и в каком порядке они ушли в голос — журнал
  «прочитано по порядку (N)» под панелью чтения (это и есть «видеть экран»);
* сверка с эталоном `/home/user/koma-lab/dense-expected.json` (мягкое сравнение
  ≥ 0,75 на реплику), порядок, дубли, обрывки, совпадение экрана и голоса;
* скриншоты `koma-lab/shots/10-page-recognized.png`, `11-reading-screen.png`,
  `12-final.png`.

`dense-a.jpg` — это ОБЛАСТЬ СТРАНИЦЫ из `data/real/dense.jpg` (кроп с 200 по 1318
по вертикали). Шапка и подвал читалки в кадр не входят: в приложении в OCR идёт
страница, а не интерфейс. Служебные полосы на всякий случай всё равно
отфильтровываются (`chromeBands`). Плагин стенда лежит в
`koma/plugins/forge-emulator.json` — правки поведения читалки идут файлом, без
пересборки.
